# Apple Music 播放列表安全删除设计

## 目标

为现有 `apple-music-playlist` 技能增加安全、可复核的删除能力，使其能够把明确批准的播放列表整理方案落地，同时避免模糊匹配、跨列表删除或整表清空。

## 方案比较

1. **按本机数据库 ID、曲名和艺人三项精确删除（采用）**：通过 Music 的结构化 JXA 接口读取并删除播放列表中的单一曲目引用。无需截图，能够在删除前后复核，风险最低。
2. **按曲名和艺人删除**：实现简单，但同一播放列表可能存在同名同艺人的不同版本，容易误删。
3. **重建整个播放列表**：能够一次得到目标顺序，但会破坏原列表身份、共享状态及用户可能依赖的元数据，超出本次范围。

## 命令和数据契约

执行层新增独立子命令：

```bash
zsh scripts/invoke.sh remove --playlist "目标列表" --input "删除清单.json" \
  --receipt-dir "调用者私有临时目录/receipts" --dry-run --json
```

删除清单中的每项必须包含：

- `databaseId`：当前 Mac 音乐资料库中的唯一数据库 ID，只接受 ASCII 数字；
- `name`：盘点时读取的精确曲名；
- `artist`：盘点时读取的精确艺人。

命令不接受 `--create` 或 `--play-first`，也不支持通配符、模糊名称、空清单清空或跨播放列表操作。
`remove` 必须通过 `--playlist` 或输入 JSON 明确指定播放列表，不继承 `add` 的历史默认值。

## 数据流

1. 读取指定用户播放列表的结构化快照，快照包含曲名、艺人和本机数据库 ID。
2. 对每个删除目标验证字段，并在该播放列表中按三项精确匹配。
3. 匹配数量不是 1 时不删除，并返回明确错误。
4. `--dry-run` 只返回将删除的目标，不修改音乐资料库，并把完整工件写入调用者提供的私有临时收据目录。
5. 收据目录通过 `lstat` 拒绝符号链接，只接受当前有效用户拥有且 group/other 无权限的目录；收据文件用 `open(O_CREAT|O_EXCL|O_WRONLY, 0600)` 原子创建。
6. 实际删除必须提供 `--approved`、原样 token 和同一收据目录。消费端对文件执行 `open(O_NOFOLLOW)` 与非阻塞独占 `flock`，在锁内完整比较工件；完全匹配才 `unlink`，不匹配保留原文件，并发或重放失败关闭。
7. 实际删除时，通过 JXA 对目标播放列表中的唯一曲目引用执行删除。
8. 每删除一首后重新读取播放列表；仅当该数据库 ID 不再存在时报告成功。
9. 单首失败不阻断其他项目，最终退出码反映是否存在失败。

## 安全边界

- 删除必须由用户在当前会话明确批准；普通推荐或添加请求不能触发删除。
- 只允许删除输入清单中已盘点、已精确确认的曲目。
- 不删除音乐资料库中的歌曲文件，不移动、不下载、不分享、不重排。
- 不提供“删除全部”或按类型自动删除的执行入口。
- 临时 JSON 和收据使用调用者创建的独立私有临时目录，完成或失败后清理；token 不写日志或长期文件。

## 测试与验收

- CLI：解析 `remove`，拒绝冲突参数、未知命令和未明确指定播放列表的删除。
- 核心：dry-run 不调用删除；精确匹配才删除；缺失或歧义不删除；删除后必须复核。
- 驱动：生成的 JXA 同时限定播放列表、数据库 ID、曲名和艺人，并要求唯一匹配。
- 包装：`invoke.sh` 能路由 `remove`，技能文档和输入规范包含确认及安全规则。
- 真实验收：先对批准的 28 首执行 dry-run，再实际删除并结构化核验 28 首均不存在；任何删除失败立即停止，不执行新增。删除全部通过后才对 20 首新增执行 dry-run 和实际新增，最后结构化读取“试音”并验证总数恰好为 50，且保留/新增清单完整、删除清单均不存在。不得先新增导致列表临时或最终变为 78 首。
