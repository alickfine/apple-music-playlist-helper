# Apple Music 精确搜索回退设计

## 背景与目标

现有 `am-playlist` 添加流程会先用准确 Apple Music URL 打开“音乐”App，再等待页面辅助功能树出现目标目录 ID。真实验收表明：部分直接打开的目录页面不会在辅助功能树中暴露曲目目录 ID，导致 20 首合法输入全部返回 `not_found`；同一台 Mac 上，通过 Music 搜索结果页进入专辑后，`TopSearchLockup` 和 `AlbumTrackLockup` 会暴露可精确校验的目录 ID。

本次开发把这条已经人工验证的路径实现为可测试、无截图、无固定坐标的 Swift 回退，使通用自然语言 Skill 在其他符合条件的 macOS 用户环境中能够独立完成添加。

## 已批准范围

- 保留现有“准确 URL 直接定位”作为第一路径。
- 第一条路径在限定时间内没有出现目标曲目 ID 时，启动 Music 搜索回退。
- 使用曲名和艺人生成搜索词，不使用仅曲名的模糊搜索。
- 通过辅助功能元素和键盘导航进入完整搜索结果，不使用截图、OCR 或固定坐标。
- 搜索结果必须出现目标曲目目录 ID，或链接中的精确专辑目录 ID。
- 进入专辑页后必须再次出现目标曲目目录 ID，才能点击该曲目的“更多”。
- 播放列表菜单项仍要求名称逐字完全一致。
- 添加后仍由 `PlaylistWorkflow` 重新读取播放列表，并以规范化后的曲名与艺人复核。
- 更新分发 Skill、中文文档、测试夹具和安装资产。

## 非目标

- 不允许按曲名、艺人或封面相似度选择目录版本。
- 不把另一个目录 ID、现场版、翻唱版或其他区服版本自动替换为目标版本。
- 不使用视觉截图、OCR、鼠标坐标或模型实时判断界面。
- 不新增删除、重排、下载、收藏、分享或账号登录能力。
- 不依赖 Apple Developer Program、MusicKit 密钥、Cookie 或账号密码。
- 不把浏览器页面作为生产回退入口。

## 方案选择

### 采用：原生 Accessibility 精确搜索回退

在 `MusicAccessibilityDriver` 内加入一个有界状态机。它使用辅助功能树识别搜索框、完整搜索结果中的目标目录节点、专辑页中的目标曲目节点和播放列表菜单项；必要的搜索快捷键与确认键通过可注入的键盘接口发送。每个跨页面阶段都重新读取辅助功能树，旧路径不跨阶段复用。

优点是仍然保持本机执行、精确目录 ID、安全失败和可自动测试；缺点是需要适配 Music 的辅助功能角色与标识符，并为页面延迟实现条件轮询。

### 未采用：浏览器链接跳转

浏览器页面会引入默认浏览器、网页地区、Cookie、弹窗和“在 Music 中打开”按钮差异，权限面更大，且仍不能保证最终专辑页暴露目标目录 ID。

### 未采用：人工可视化回退

人工回退已经证明搜索路径可行，但依赖模型观察和点击，无法成为任何人可安装、可重复运行的第一版 Skill。

## 架构调整

### `AccessibilityProviding`

扩展为支持以下窄能力：

- 读取 Music 辅助功能树；
- 按稳定路径执行按钮或结果项；
- 为可设置的搜索文本框写入字符串；
- 向 Music 发送明确的快捷键或导航键。

生产实现只操作 `com.apple.Music`。测试实现记录调用并按预设树序列返回结果。

### `AccessibilityMatcher`

新增纯函数匹配器：

- 查找可设置的 Music 搜索框；
- 在 `TopSearchLockup` 中查找精确曲目目录 ID；
- 在 `TopSearchLockup` 或 `SquareLockup` 中查找精确专辑目录 ID；
- 在 `AlbumTrackLockup` 中查找目标曲目的“更多”；
- 所有目录 ID 使用完整数字 token 比较，拒绝前缀、后缀和包含关系。

匹配器不得使用曲名或艺人作为最终写入依据。曲名和艺人只用于缩小搜索结果，目录 ID 才是授权点击的依据。

### `MusicAccessibilityDriver`

添加流程分为两个阶段：

1. **直接 URL 阶段**：保持现有行为，在分配给该阶段的时间内查找目标 `AlbumTrackLockup`。
2. **精确搜索阶段**：
   - 聚焦 Music 搜索；
   - 写入“曲名 艺人”；
   - 使用键盘选择完整搜索结果；
   - 等待目标曲目 ID；若曲目不在首选结果中，则等待链接内精确专辑 ID；
   - 按下匹配结果并进入专辑；
   - 等待目标 `AlbumTrackLockup`；
   - 点击其“更多”，选择名称完全一致的播放列表。

总超时仍由调用者的 `--timeout` 控制。两个阶段共享同一个最终期限，不能让回退无限延长单首处理时间。轮询采用条件等待，不使用固定长睡眠。

## 专辑 ID 解析

从已经通过输入校验的 Apple Music URL 路径中提取 `/album/<slug>/<album-id>` 的最后一个纯数字路径段。提取失败时仍可使用精确曲目 ID 搜索，但不得猜测专辑 ID。URL 的 `i` 查询参数继续要求与曲目 ID 完全相同。

## 错误与安全行为

- 找不到搜索框：该曲目返回 `not_found`，不发送输入到其他控件。
- 搜索结果没有目标曲目 ID 或目标专辑 ID：返回 `not_found`。
- 进入专辑后没有目标曲目 ID：返回 `not_found`。
- 目标曲目节点下没有“更多”：返回 `not_found`。
- 找不到名称完全一致的播放列表菜单项：返回 `not_found`。
- 辅助功能路径在按压或设置值前失效：抛出明确驱动错误，由工作流记录为 `failed`。
- 任一失败都不降级为曲名近似点击，也不妨碍后续曲目继续处理。

## 测试设计

### RED 测试

先增加失败测试，覆盖：

- 直接 URL 页面没有目录 ID时会进入搜索回退；
- 搜索框只接受精确路径设置；
- 完整搜索结果中只有目标目录 ID 可被按压；
- 目标曲目不在首选结果时可由精确专辑 ID 进入；
- 专辑页必须再次出现目标曲目目录 ID；
- 相邻数字、相似曲名、现场版目录 ID和同名播放列表不会被误选；
- 总期限耗尽后不再执行任何写入；
- 20 首和 100 首输入不截断，失败项不阻断后续项。

### GREEN 实现

只实现使上述测试通过的状态机、匹配器和协议能力，不进行无关重构。

## 真实 Music 验收

在用户已批准的范围内创建一个名称带日期和“测试”字样的临时播放列表，选择一首当前 storefront 可用且不在该临时列表中的曲目：

1. dry-run 返回可添加；
2. 实际添加走新回退并返回 `added`；
3. 写后复核找到准确曲名与艺人；
4. 相同输入再次运行返回 `skipped_duplicate`，曲目数不变。

测试播放列表不自动删除，避免未经单独批准的删除；最终报告其准确名称，供用户保留或手动删除。

## 完成标准

- 生产添加路径不依赖模型、截图、OCR 或固定坐标。
- 直接 URL 失败时，精确搜索回退能够在真实 Music 中新增一首曲目。
- 每次写入都由目标目录 ID 在搜索结果页和专辑页两次校验后触发。
- 不可用或不唯一的目录版本安全返回失败，不自动替换。
- 自动化、分发包、全新安装和真实 Music 验收全部通过。
- 中文 Skill 文档准确描述回退、权限、失败状态和安全边界。
