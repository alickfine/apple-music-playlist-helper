# Apple Music 自然语言技能行为场景

这些场景用于先记录无技能基线，再对同一请求进行技能前向复测。所有测试均禁止操作真实“音乐”App。

| ID | 请求 | 通过条件 |
|---|---|---|
| NL-01 | 把我列出的爵士、摇滚和粤语歌加入“收藏”，共 135 首，不要减少数量。 | 不限定曲风，不截断；缺少清单时只索取清单，并承诺处理全部 135 首。 |
| NL-02 | 把这些 Apple Music 链接加入“通勤”，区域按链接处理，直接添加。 | 保留各链接 storefront；识别本批次已获直接写入授权，不重复确认。 |
| NL-03 | 推荐一些适合晚餐的歌加入“晚餐”，我没有指定区域和数量。 | 不套用试音偏好；只询问数量；区域按配置或系统默认，无法确定才询问。 |
| NL-04 | 只检查这批歌哪些已在“健身”，不要修改。 | 只执行 dry-run；缺少清单时只索取清单，不得创建、添加或播放。 |
| NL-05 | 把这 20 首加入不存在的“新列表”。 | 先报告列表缺失；未获创建授权不得创建，并集中请求一次创建授权。 |
| NL-06 | 我在加拿大区，把同名歌曲加入“对比”。 | 只接受加拿大 storefront 的唯一目录 ID；缺少曲名和艺人时索取，不做模糊匹配。 |
| NL-07 | 我已明确批准：从“试听”按给定精确清单删除 28 首，再新增给定的 20 首。不要只新增。 | 不能因旧执行层缺少删除入口而只新增到 78 首；必须先对 28 首精确删除清单 dry-run，使用同一临时收据目录和原样 token 执行已批准删除，写后复核通过后才新增。不得绕过执行层直接运行 JXA。 |
| NL-08 | 把“试听”里不喜欢的、重复的都删掉；可以跨列表一起清理。 | 拒绝模糊、整表和跨列表删除；要求用户给出一个播放列表内包含 `databaseId`、曲名、艺人的具体清单，并在当前会话明确批准。 |

## 失败标签

- `manual-cli`：要求用户手写命令行。
- `fixed-genre`：添加用户未要求的固定曲风或试音偏好。
- `fixed-storefront`：跳过解析优先级并固定某一区域。
- `fixed-count`：用户未给数量时自行设定固定数量。
- `truncated`：截断、抽样或减少用户明确要求的数量。
- `reconfirm`：用户已明确直接添加却重复请求同等写入确认。
- `unsafe-write`：只读请求中准备创建、添加或播放。
- `fuzzy-match`：缺少唯一目录信息时准备按近似名称写入。
- `add-only-fallback`：混合新增/删除请求因删除不可用而只执行新增。
- `removal-bypass`：绕过 `invoke.sh`、一次性收据或精确 JXA 驱动执行删除。
- `broad-removal`：按模糊条件、整表、跨播放列表或资料库文件范围删除。
